</objective>

<constraints>
- **Snapshot-driven only.** The store holds the latest `RoomSnapshot`; every screen renders purely from it. Never derive client-side game state that the snapshot already provides. `server/test/helpers.ts` (`playToVictory`) is the canonical example of driving a client from snapshots alone.
- **sessionId is a resume credential** (02-01 decision): persist it in `sessionStorage`, NOT `localStorage` — per-tab storage means two tabs of one browser are two distinct players (essential for local testing), while a refresh within a tab resumes the same session. Never display or log it.
- Vite dev proxy already forwards `/socket.io` (ws: true) to :3001 — connect socket.io-client to same-origin default, no URL/CORS config.
- Pure ESM; client tsconfig uses Bundler resolution — bare `@steel-horizon/shared` imports, no `.js` suffix needed in client code.
- No router library. Phase-based rendering from the snapshot (`snapshot.phase`) is the routing. No URL state beyond the `?code=` join prefill.
- Plain 2D, hand-written CSS. Functional and clean, zero effort on beauty — Phase 4/5 replaces the visuals.
</constraints>

<task type="auto">
  <name>Task 1: Socket connection layer and snapshot-driven Zustand store</name>
  <files>client/package.json, client/src/socket.ts, client/src/store.ts</files>
  <action>
    Add `socket.io-client@^4` and `zustand@^5` to client dependencies (`npm install` from repo root). Add a `"typecheck": "tsc --noEmit"` and `"build": "tsc --noEmit && vite build"` script to client/package.json.

    `client/src/socket.ts`: create a typed singleton `Socket<ServerToClientEvents, ClientToServerEvents>` using the shared protocol types. Construct it with `autoConnect: false` and `auth` populated from `sessionStorage` (`sessionId`, `name`) via a callback-form auth (socket.io re-evaluates callback auth on every reconnect attempt, so a mid-session mint is picked up). Export a `connect(name: string)` helper that stores the name in sessionStorage, sets auth, and connects.

    `client/src/store.ts`: Zustand store with:
    - `snapshot: RoomSnapshot | null` — set verbatim from every `roomState` event
    - `connection: "idle" | "connecting" | "connected" | "disconnected"` — from socket lifecycle events
    - `lastError: { code: ErrorCode; message: string } | null` — from `errorEvent`, clearable
    - `shotFeed: Array<{ shooter: string; target: Coordinate; result: ShotOutcome; sunkShip?: ShipClassId }>` — appended from `shotResult` events (03-03 renders this as the shot log; keep it in the store now so listeners are registered exactly once)
    - actions that emit `createRoom` / `joinRoom` / `quickMatch` / `setReady` (thin wrappers around socket.emit; connect first if not connected)

    Register all socket listeners ONCE at module init (not inside React effects — StrictMode double-mount would duplicate them). On `session`, persist `sessionId` to sessionStorage. On `roomState`, replace the snapshot. Wipe `shotFeed` when a snapshot arrives whose phase is `placement` and the previous snapshot's phase was not `placement` (fresh game or rematch reset).
  </action>
  <verify>`npm run typecheck --workspace @steel-horizon/client` passes. With `npm run dev` running, a quick node script (or browser console) confirms connecting yields a `session` event and sessionStorage holds the sessionId after `connect("Test")`.</verify>
  <done>Typed socket singleton + store exist; `roomState` replaces the snapshot; sessionId round-trips through sessionStorage so a page refresh reconnects with the same identity.</done>
