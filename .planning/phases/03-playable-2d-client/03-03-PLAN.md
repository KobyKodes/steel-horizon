<constraints>
- **Everything renders from the snapshot**: `yourShots` / `shotsAgainstYou` (each `ShotRecord` has target, result, optional sunkShip), `currentTurn` ("you" | "opponent" | null), `opponent.sunkShips`, `winner`, `winReason`, `revealedOpponentFleet` (non-null ONLY at gameover — the wire contract guarantees no earlier fleet data exists to leak), `rematch.{youRequested,opponentRequested}`. The `shotFeed` store array (from 03-01) exists for the chronologically interleaved log; after a refresh it reseeds empty — rebuild what you can from the snapshot's two shot arrays and accept lost interleaving.
- `shotResult.shooter` is a display name, never a sessionId (02-02 decision) — safe to render verbatim.
- Fire by emitting `fire({ target })` with 0-based `Coordinate`; render labels via `coordToLabel`. The server rejects NOT_YOUR_TURN / CELL_ALREADY_SHOT / OUT_OF_BOUNDS — the client should also disable those interactions locally (already-shot cells unclickable, board inert when it's not your turn) but server rejection must degrade gracefully to the error banner, never crash.
- No firing cinematics, no turn timers, no coin-flip animation — Phases 5 and 6. A plain text/color turn indicator suffices.
- This plan exclusively owns battle/post-game files; do not touch App.tsx, PlacementScreen, or placement files (03-02 runs in parallel). Additive store actions (`fire`, `requestRematch` emit wrappers) are permitted if 03-01 didn't create them.
</constraints>
