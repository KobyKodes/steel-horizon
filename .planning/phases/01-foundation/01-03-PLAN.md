<feature>
  <name>Fleet placement validation + random fleet generation</name>
  <files>shared/src/placement.ts, shared/src/placement.test.ts</files>
  <behavior>
    `validateFleetPlacement(fleet: FleetPlacement): PlacementValidation` where PlacementValidation is { valid: true } | { valid: false; reason: "WRONG_FLEET_COMPOSITION" | "OUT_OF_BOUNDS" | "OVERLAP" }.

    Cases (each its own test):
    - A known-good fleet (all 5 ships, in bounds, disjoint) → valid: true
    - Ships touching side-by-side (adjacent rows/cols, no shared cell) → valid: true (classic rules: touching allowed — this test exists to prevent someone "helpfully" adding a no-touch rule later)
    - Horizontal carrier at origin col 6 (G1) → cells run off column J → OUT_OF_BOUNDS
    - Vertical destroyer at row 9 (row "10") → runs off bottom → OUT_OF_BOUNDS
    - Origin itself off-board (negative or ≥10) → OUT_OF_BOUNDS
    - Two ships sharing any cell → OVERLAP
    - Missing a ship class (4 ships) → WRONG_FLEET_COMPOSITION
    - Duplicate ship class (two destroyers, even if 5 total) → WRONG_FLEET_COMPOSITION
    - Empty array → WRONG_FLEET_COMPOSITION
    - Composition is checked against FLEET from fleet.ts, not hardcoded strings

    `generateRandomFleet(): FleetPlacement`
    - Property test: 200 iterations, every generated fleet passes validateFleetPlacement
    - Returns a NEW random layout each call (generate 20, expect at least 2 distinct layouts — guards against a constant "random" placement)
  </behavior>
  <implementation>

  </implementation>
