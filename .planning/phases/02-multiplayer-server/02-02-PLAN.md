  <name>Task 1: Pure game engine state machine (test-first)</name>
  <files>server/src/game/engine.ts, server/src/game/engine.test.ts</files>
  <action>
Write the tests alongside/before the engine (this is the highest-risk logic in Phase 2 — pin every rule). The engine is a pure module: no socket.io import, no timers, no I/O. It composes the shared rule functions per the 01-04 decision ("rule functions stay pure; server composes state around them").

`createGame(playerIds: [string, string], rng: () => number)` → `Game` state:
- Per player: `fleet: FleetPlacement | null`, `shots: ShotRecord[]` (shots FIRED by that player, appended by the engine after resolution — respect 01-04's contract that resolveShot receives the history BEFORE the shot).
- `phase: "placement" | "battle" | "gameover"`, `currentPlayer: string | null`, `winner: string | null`, `winReason`, `rematchRequests: Set<string>`.
- rng is injected so tests and the 02-03 scripted games can force deterministic coin flips.

Transitions (each returns a discriminated union `{ ok: true; ... } | { ok: false; code: ErrorCode }` per the established 01-03/01-04 pattern; on `ok: false` state is untouched):
- `placeFleet(game, playerId, fleet)`: WRONG_PHASE unless placement; validate with shared `validateFleetPlacement` → INVALID_PLACEMENT on failure; a player may re-place while still in placement phase (idempotent overwrite) — placement is simultaneous. When BOTH fleets are set, transition to battle and coin-flip `currentPlayer` with rng.
- `fire(game, playerId, target)`: WRONG_PHASE unless battle; NOT_YOUR_TURN unless currentPlayer; resolve with shared `resolveShot` against the OPPONENT's fleet and the shooter's shot history (propagate OUT_OF_BOUNDS / CELL_ALREADY_SHOT); append the ShotRecord; on sunk include sunkShip; check `isFleetDestroyed` → gameover with winner + winReason "all-ships-sunk"; otherwise alternate currentPlayer. Turn ALWAYS alternates after a valid shot — hits do not grant extra turns (classic alternating rules per PROJECT.md).
- `requestRematch(game, playerId)`: WRONG_PHASE unless gameover; record request; when both have requested, return a fresh game (new createGame with same players, fresh rng coin-flip, empty boards) — both-must-accept semantics.
- `forfeit(game, playerId)` → gameover, opponent wins, winReason "forfeit" (used by 02-03's grace timer; cheap to include and test now so 02-03 doesn't reopen the engine).

Test coverage (Vitest): placement rejection paths, re-place during placement, both-placed → battle with rng-forced first player (test both outcomes), NOT_YOUR_TURN, WRONG_PHASE for every event in every wrong phase, hit/miss/sunk propagation, repeat-shot rejection leaves turn unchanged, full scripted game to win (sink all 17 cells), turn alternation after hit AND miss, rematch requires both, rematch resets boards/shots, forfeit. State-untouched-on-rejection pinned by at least one test doing a deep-equal before/after.

<task type="auto">
  <name>Task 2: Snapshot redaction and game-loop socket handlers</name>
  <files>server/src/snapshot.ts, server/src/socket.ts, server/src/rooms.ts</files>
  <action>
server/src/snapshot.ts: move/extend 02-01's lobby snapshot builder into the single `buildSnapshot(room, viewerSessionId): RoomSnapshot` covering all phases. Redaction rules (DISCOVERY §3 — this function is the anti-cheat choke point):
- `you.fleet` = viewer's own placement (null until placed).
- `yourShots` = viewer's ShotRecords; `shotsAgainstYou` = opponent's ShotRecords.
- `opponent.sunkShips` derived from the viewer's shots' sunk results.
- `revealedOpponentFleet` = opponent's FleetPlacement ONLY when phase is gameover, else null. No other code path may serialize the opponent fleet.
- `currentTurn`/`winner` mapped to viewer-relative "you"/"opponent".

Wire the engine into rooms.ts/socket.ts:
- Room's `game` slot holds the engine Game once phase leaves lobby; when 02-01's both-ready flip happens, call `createGame` with `Math.random` as the injected rng (keep the rng passed through room creation so tests can override).
- `placeFleet` handler: NOT_IN_ROOM / delegate to engine; on acceptance re-snapshot both players. Do NOT echo the fleet to the opponent in any form.
- `fire` handler: delegate to engine; on acceptance emit `shotResult { shooter, target, result, sunkShip? }` to the room (cinematic cue — information both sides may know) and re-snapshot both players; on gameover the next snapshots carry winner + revealedOpponentFleet.
- `requestRematch` handler: delegate; when a rematch resets the game, room phase returns to "placement" and both players get fresh snapshots (ready flags/boards reset).
- Every rejection → `errorEvent` with the engine's code to the offending socket only; no snapshot, no state change.
  </action>

  <done>Complete game playable over sockets; buildSnapshot is the only serialization path for board state; opponent fleet reaches the wire only at gameover.</done>
