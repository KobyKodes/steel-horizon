<task type="auto">
  <name>Task 2: Room registry, matchmaking queue, and lobby handlers</name>
  <files>server/src/rooms.ts, server/src/matchmaking.ts, server/src/socket.ts</files>
  <action>
server/src/rooms.ts:
- `Room` type: `code`, `players` (map/array of up to 2 `RoomPlayer { sessionId; name; ready: boolean; connected: boolean }`), `phase: RoomPhase` (starts "lobby"), plus a `game: unknown | null` slot the 02-02 engine will occupy.
- `RoomStore` interface (`create/get/delete`) + `InMemoryRoomStore` (Map keyed by code).
- `generateRoomCode(isTaken: (code: string) => boolean)`: 6 chars from unambiguous alphabet (A–Z minus I and O, digits 2–9); loop on collision. Pure and injectable so it unit-tests without a store.

server/src/matchmaking.ts: FIFO queue of `{ sessionId; name }`. `enqueue` rejects a sessionId already queued or already in a room; when two distinct sessions are waiting, dequeue both and return a pairing for the socket layer to create a room from. Pure module (no socket.io import) so it unit-tests directly. Remove a session from the queue on disconnect.

Handlers in server/src/socket.ts (every inbound payload is hostile — validate everything, reply with typed `errorEvent` and make no state change on rejection):
- `createRoom { name }`: validate name (trim, 1–20 chars, else INVALID_NAME); reject if session already in a room (ALREADY_JOINED); create room, join socket to the Socket.IO room, set session.roomCode.
- `joinRoom { name, code }`: normalize code to uppercase; ROOM_NOT_FOUND / ROOM_FULL / ALREADY_JOINED (double-join: same session joining any room twice, including its own); on success join + fill second slot.
- `quickMatch { name }`: enqueue; on pairing, create a room and join both sockets.
- `setReady { ready }`: NOT_IN_ROOM if no room; WRONG_PHASE unless lobby; set flag. When both players are ready, set phase to "placement" (the 02-02 engine takes over from there; for now the phase flip in the snapshot is the observable outcome).
- After EVERY accepted mutation, send each player in the room their own `roomState` snapshot via a `buildLobbySnapshot(room, viewerSessionId)` helper (game fields null/empty at this phase). Per-viewer sends only — never broadcast one snapshot to the room (snapshots are viewer-specific by design).
  </action>

  <done>Two sockets can create/join (or quick-match into) a room, ready up, and both observe phase flip to "placement" through their snapshots; all invalid paths return typed errors without corrupting state.</done>
