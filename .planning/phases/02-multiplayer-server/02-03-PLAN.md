<task type="auto">
  <name>Task 1: Session-resume reconnect, disconnect grace, and forfeit</name>
  <files>server/src/socket.ts, server/src/rooms.ts, server/src/session.ts, server/src/config.ts</files>
  <action>
server/src/config.ts: `RECONNECT_GRACE_MS` (default 60_000, overridable — read from an options object passed into the server factory so tests inject ~100ms; env override optional).

Disconnect handling (socket `disconnect` event):
- Session in a live room: mark that RoomPlayer `connected: false`, re-snapshot the opponent (their snapshot's `opponent.connected` flips — that IS the disconnect notification, no new event type), and start a per-player grace timer.
- Grace expiry during placement or battle: call the engine's `forfeit(game, disconnectedPlayerId)` (built in 02-02) → gameover, opponent wins, winReason "forfeit"; re-snapshot the remaining player. If the room is still in lobby, just remove the player (opponent snapshot shows them gone; a solo lobby stays open for a new joiner).
- Track timers per room+player and CLEAR them on reconnect — a stale timer firing after reconnect would forfeit a live player (test this explicitly).
- Room cleanup: when both players are disconnected past grace (or gameover room fully abandoned), delete the room and null out the sessions' roomCode so codes free up and the store doesn't leak.

Reconnect (in the connection handler, after 02-01's session middleware):
- If the connecting sessionId maps to a live room: rejoin the Socket.IO room, set `connected: true`, cancel the grace timer, emit a full `roomState` snapshot to the reconnecting client (buildSnapshot already carries everything: phase, own fleet, both shot histories, turn, winner — this is the whole resume mechanism per DISCOVERY §2), and re-snapshot the opponent so their `opponent.connected` flips back.
- Reconnect must work identically in lobby, placement, battle, and gameover phases — no phase-special resume code beyond what buildSnapshot already encodes.
- A second live socket connecting with the SAME sessionId while the first is still connected: treat as the player's newest tab — disconnect the old socket and hand the room to the new one (refresh often connects the new socket before the old one's disconnect fires; last-connect-wins is the refresh-proof choice).
  </action>

  <done>Disconnect flips opponent-visible connected flag and starts grace; reconnect within grace fully restores play from the snapshot alone; grace expiry forfeits in favor of the opponent; no timer leaks across reconnects; abandoned rooms are deleted.</done>
