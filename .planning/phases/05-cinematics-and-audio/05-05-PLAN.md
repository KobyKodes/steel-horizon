  <action>
Create `FleetStatusPanel`, a plain HTML/CSS component (no 3D — this is HUD chrome, not scene content) rendering a small silhouette row per ship: a horizontal strip of `SHIP_LENGTHS[ship]` segments (small rectangles/blocks) representing that ship's hull length. Props:
```typescript
export interface FleetStatusEntry {
  ship: ShipClassId;
  hits: number;      // segments to render as damaged, left-to-right
  length: number;     // SHIP_LENGTHS[ship]
  sunk: boolean;
}
export interface FleetStatusPanelProps {
  title: string;
  entries: FleetStatusEntry[];
}
```
Each ship row shows its name, then `length` small segments; the first `hits` segments render in a damage color (red/orange), remaining segments in a neutral "intact" color (matching the existing holographic teal palette used elsewhere in the HUD — check `battle.css`/`placement.css` for the established accent colors and reuse them, don't invent a new palette). A fully sunk ship's row gets an additional dimmed/struck-through treatment (e.g., reduced opacity + a "SUNK" label) distinct from a partially-damaged-but-alive ship. This is a straightforward presentational component — no animation timing/sequencing logic belongs here (that's scene-side, from 05-03/05-04); it just reflects current damage state each render.

Note: for the opponent's fleet-status panel (BattleScreen's `battle-main` section, which only knows `opponent?.sunkShips`, not per-cell hit counts against them), reuse the same component but only meaningfully populate the `sunk` boolean per ship — omit or gray out the per-segment fill since that data isn't available to this client until game end (server never reveals opponent ship positions early, per the anti-cheat design in PROJECT.md). Do not attempt to infer opponent damage counts from anything client-side.
