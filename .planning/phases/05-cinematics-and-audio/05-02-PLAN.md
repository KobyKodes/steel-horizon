<task type="auto">
  <name>Task 2: Build the reusable ParticleBurst component</name>
  <files>client/src/scene/effects/ParticleBurst.tsx</files>
  <action>
Create `ParticleBurst`, a component that renders a `THREE.Points` object driven by a `BufferGeometry` with per-vertex position/velocity attributes, integrated in `useFrame`. Props:
```typescript
export type BurstPreset = "splash" | "explosion" | "debris";
export interface ParticleBurstProps {
  preset: BurstPreset;
  origin: [number, number, number]; // world position where the burst spawns
  onComplete?: () => void; // called once the burst's lifetime elapses, so callers can unmount it
}
```
Internals:
- On mount, generate `count` particles (splash ~40, explosion ~80, debris ~30 — tune by eye) with randomized initial velocities: splash = mostly upward + outward cone (teal-white per the checkpoint:decision if "unified-teal" was chosen, or white/foam-colored if "layered" was chosen — splash is water, not fire, so it may look the same either way; use judgment based on the decision's resolution), explosion = fast outward sphere with colors resolved from the checkpoint:decision (warm orange/red/gray for "layered", teal/white for "unified-teal"), debris = slower outward + gravity-affected, darker/longer-lived, colors likewise resolved from the decision.
- Each frame in `useFrame`: integrate each particle's position by velocity * delta, apply a simple downward gravity constant to `debris` and `splash` presets (not `explosion`, which should look weightless/expanding), fade opacity linearly over the preset's lifetime (splash ~0.6s, explosion ~0.8s, debris ~2.5s), and call `onComplete?.()` once elapsed time exceeds the preset's lifetime (guard so it only fires once).
- For the `splash` preset specifically, per 05-RESEARCH.md Pitfall 2: if the burst needs to know the water surface height at `origin` (e.g., to spawn slightly above/at the live wave surface rather than a fixed Y), sample it via `gerstnerHeight(origin[0], origin[2], clock.elapsedTime)` from `../waves` — do NOT hand-roll an independent height approximation.
- Use `THREE.AdditiveBlending` on the material for explosion/splash per the research's particle rendering guidance (creates the saturated glow look); debris should use normal blending since it represents solid matter, not light/water spray.
- Memoize the geometry/material per preset the way `ShipModel` memoizes per class (04-02 pattern) so repeated bursts across a game don't rebuild materials from scratch each time — but per-instance particle position/velocity arrays are per-burst state and cannot be shared, only the `PointsMaterial`/blending config can be a shared preset-keyed constant.
