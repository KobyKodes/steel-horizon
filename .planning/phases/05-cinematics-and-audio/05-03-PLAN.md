<task type="auto">
  <name>Task 1: Build ShellProjectile (parabolic arc + smoke trail)</name>
  <files>client/src/scene/effects/ShellProjectile.tsx</files>
  <action>
Create `ShellProjectile`, a component that animates a small mesh (a simple elongated sphere/cone, a few tenths of a world unit) from a start world position to an end world position along a parabolic arc over a fixed duration, using drei's `useTrail` for the smoke trail.

```typescript
export interface ShellProjectileProps {
  start: [number, number, number];
  end: [number, number, number];
  durationSeconds: number; // caller-supplied, must keep the whole firing sequence ≤2.5s total per ROADMAP.md
  arcHeight?: number; // default a modest world-unit peak height
  onImpact: (impactPosition: [number, number, number]) => void; // fires once, at flight completion
}
```
- Compute position each frame as `t = elapsed / durationSeconds` (clamp to [0,1]), apply an ease-in-out curve to `t` before using it in the lerp (per 05-RESEARCH.md Pitfall 3: perceived "slow/cinematic" feel comes from easing, not raw duration — a linear arc across the whole 10x10 grid at a fixed short duration will look too fast otherwise). Use the standard parabola formula from 05-RESEARCH.md: `pos = lerp(start, end, easedT); pos.y += arcHeight * 4 * easedT * (1 - easedT)`.
- Attach `useTrail(meshRef.current, { length: 6, decay: 0.9, local: false, stride: 0.1, interval: 1 })` per the verified drei API in 05-RESEARCH.md (return type is a `Float32Array` ref, not `Vector3[]` — read it accordingly) and render it via drei's `<Trail>` wrapper or by driving a `MeshLine` from the returned points, whichever is simpler given the installed API surface — check `node_modules/@react-three/drei/core/Trail.d.ts` directly if the exact usage is unclear rather than trusting web docs.
- Call `onImpact(currentPosition)` exactly once when `t` reaches 1, then the component should render nothing further (parent unmounts it based on the callback).
- Do NOT parent the shell as a child of the camera or attach the camera as a child of the shell — 05-01's `shellFocus` prop on CameraRig is how the camera tracks the shell; this component only owns the shell mesh + trail.
  </action>

  <done>Shell travels start→end along an eased parabolic arc within durationSeconds, trail renders and fades behind it, onImpact fires exactly once</done>

  <action>
Add sequencing state so a newly-arrived shot plays its cinematic before its marker appears on the grid:

1. In `GameSceneAdapter`, track which shots have already "settled" (finished animating or arrived before this feature existed) versus a single "pending" shot currently animating. On mount, treat all shots already present in the initial `shots` prop as settled (no animation on first load/reconnect — only NEW shots arriving after mount should animate). Detect a new shot by comparing the incoming `shots` array length/last-entry to the previously-seen array (e.g., via a ref holding the last-seen shot count).
2. When a new shot is detected: withhold it from `cellStatesFrom`'s input (pass only settled shots to that function) and instead render a `ShellProjectile` from the firing ship's approximate world origin (use a fixed launch point — e.g., a point just outside the grid edge on the shooter's side, since the firing ship's exact position isn't tracked by this adapter) to `cellToWorld(shot.target)` at the water surface / grid altitude. Pass `shellFocus` up through `SceneRoot`/`CameraRig` (05-01's new prop) tracking the shell's live position each frame while it's in flight.
3. On the shell's `onImpact` callback: trigger `triggerCameraShake` (05-01) scaled by whether the shot was a hit/sunk (bigger) or miss (smaller/none), mount a `ParticleBurst` (05-02) with preset `"explosion"` for hit/sunk or `"splash"` for miss at the impact position, and mark the shot as settled once the burst's `onComplete` fires (or after a fixed short delay — whichever keeps total sequence time bounded) — only then does it join `cellStatesFrom`'s settled list and the actual hit/miss/sunk marker appears on the grid.
4. Add a skip mechanism per ROADMAP.md ("each ≤2.5s and skippable"): a click/tap anywhere on the scene during an active sequence, or a fixed key (e.g., Escape or Space), immediately marks the pending shot settled and cancels the in-flight shell/burst/shake. If a prop threading change to `BattleScreen.tsx` turns out to be unnecessary after implementation, leave that file untouched and note it in the summary.
